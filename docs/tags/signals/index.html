The Bugs Were Our Own Linker Wraps: Making a PHP Timeout Actually Time Out

In the stack guard post the villain was a -Wl,--wrap linker flag that turned off PHP’s C-stack overflow guard. It wasn’t the only one. Until August, max_execution_time did nothing in ePHPm on Linux, for the same reason: we had wrapped the function that arms it to a no-op. A runaway script ran until the HTTP layer’s request timeout gave up on it and sent a 504, and the PHP thread kept burning CPU after that.

We Disabled PHP's Stack Guard Ourselves: Containing Segfaults in a Single-Process PHP Server

How ePHPm went from dying silently on a segfault to containing stack overflows per thread, and the linker flag that had turned off PHP's own guard.

September 6, 2026

12-Minute Read

php-fpm has a property nobody thinks about until they leave it: when a worker segfaults, you lose one request. The master forks a new child and life goes on. ePHPm runs every tenant’s PHP as threads inside one process. That’s where the memory and latency wins come from, and it also means one tenant’s segfault takes down every other tenant on the box.
