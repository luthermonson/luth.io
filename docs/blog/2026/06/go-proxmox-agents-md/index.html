Maintaining an Open-Source Library With AI Agents: AGENTS.md and the Rule They Kept Breaking

Six weeks of go-proxmox with coding agents doing most of the typing: what went into AGENTS.md, the API shape five parallel agents got wrong the same way, and how a coverage metric bent the code around it.

June 27, 2026

7-Minute Read

Email

On May 9th I merged #264, which added an AGENTS.md to go-proxmox and a stub CLAUDE.md that just points at it. Over the next six weeks, through the v0.8.0 migration guide on June 15th, main took 77 commits, +31,794 / -1,144 lines, went from 84 to 186 .go files, and endpoint coverage went from 30% to 100% of the Proxmox API. Most of that code was typed by coding agents, a lot of it by several at once. This is what that looked like from the maintainer’s chair, mostly the parts that went wrong, because that’s where AGENTS.md got its content.

What’s in the file

The first version was boring on purpose: how to build and test (Mage targets, which env vars the integration suite reads, that CI only runs unit tests), how a request flows through Client.Req, the client.Node(ctx, name) to node.VirtualMachine(ctx, id) to *Task traversal, and a handful of gotchas like the ~16 KB upload cap. The one required section was about tests: any PR that adds or changes an endpoint ships a gock mock in tests/mocks/pve9x/<resource>.go and a unit test with a happy path and at least one error path. Integration tests need a live cluster and CI doesn’t have one, so without that rule an agent can write a wrapper that has never executed and the green check means nothing.

Everything else in the file today was added after something went wrong.

Five agents, one rule, five times

The coverage push went area by area, and the big areas were split into groups and handed to sub-agents in parallel. For qemu that was five PRs, #301 through #305, each one fine on its own. They all appended to the same virtual_machine.go, types.go and mock file, so merging them one at a time meant a four-way rebase. I closed all five and cherry-picked them into #306 with the per-feature commits kept. That became the pattern: parallel branches, one combined PR.

Ceph (#307) was five agents on 41 endpoints, and the combined PR needed a cleanup commit for placement alone. Two groups put their mocks in the existing ceph.go, two appended them to nodes.go, and one created a new nodes_ceph.go and registered a second, duplicate loader for it. Three of them wrote the identical func cephNode() *Node test helper in three files. None of that is wrong code, it’s five people who didn’t talk to each other, which is exactly what it was.

The bigger problem showed up in the method signatures. Several agents independently produced this:

node.CephOSDScrub(ctx, id, deep)
node.DeleteCephOSD(ctx, id, cleanup)
node.CephOSDLVInfo(ctx, id, ...)

Every OSD operation hung off *Node with the OSD id threaded through as an argument. It compiles, it works, and it’s not the shape the rest of the library uses. Storage, VMs, containers and network interfaces all have a getter that returns a handle, and the operations live on the handle. The Proxmox schema even tells you which one to use: the path is /nodes/{node}/ceph/osd/{osdid}/scrub, and the {osdid} segment says “this is one of many”. Once I looked, the same thing had happened to node services, node replication jobs, firewall rules on nodes, VMs and containers, and snapshots. Fixing it took a refactor commit inside #307 plus four PRs, #308 to #311, and the last two were breaking changes to methods that had already shipped.

The fix that matters is #312, which turned it into a rule with no judgement call in it:

// Getter: no API call, just constructs the handle.
func (n *Node) CephOSD(id int) *CephOSD {
    return &CephOSD{client: n.client, Node: n.Name, ID: id}
}

// Operations live on the instance, not the parent.
func (o *CephOSD) Scrub(ctx context.Context, deep bool) error { … }
func (o *CephOSD) Delete(ctx context.Context, cleanup bool) (*Task, error) { … }

plus an explicit anti-pattern line naming node.CephOSDScrub(ctx, id, ...), a note that creation stays on the parent because there’s no instance yet, and a list of every existing handle type to copy. The cluster SDN sweep that came after it (#320) has handle types throughout: *SDNController, *VNet, *VNetSubnet and friends. The lesson I took: “follow the existing patterns” is not an instruction. An agent sees one file at a time and the pattern isn’t in that file. “Look at the upstream path, if it has /{id}/ write a getter” is an instruction.

They optimize for the gauge you give them

Coverage was the scoreboard for this work, and the scanner that computes it is a set of regexes looking for client.Get(ctx, fmt.Sprintf("/nodes/%s/...", ...)). Agents read the scanner’s output after every change, and twice they changed the code so the scanner would count it:

  • The Ceph group writing start/stop/restart first built them through a shared cephServiceAction(action, ...) helper, then inlined three copies, because the path normalizer turned fmt.Sprintf("/nodes/%s/ceph/%s", node, "start") into /nodes/{}/ceph/{}, which doesn’t match /nodes/{node}/ceph/start.
  • Another group rewrote a GetWithParams call into the url.URL{Path: ...} form because the scanner understood one and not the other.

Both were noted honestly in the PR bodies, which is the only reason I know. Neither is terrible code, but the duplication in the first one exists only to satisfy a tool. The right response was to fix the tool, and #313 taught the scanner about *WithParams. That went into AGENTS.md too: if a wrapper is invisible to the scanner, prefer teaching the scanner over contorting the code or adding to the exclusion list. If you hand an agent a number to move, decide in advance what it’s allowed to change to move it.

Rules written after the second time

The rest of the file reads like a list of reviews I didn’t want to write again:

  • Pointer fields for non-zero Proxmox defaults (#271), with the decision procedure spelled out: look up the default, pointer if it differs from Go’s zero, regression test both ways.
  • Comment every pointer field with the default it protects. That one exists because a large wrapper PR (#274) did the pointer conversion correctly and deleted the FIXME comments explaining why, leaving bare *int fields that look like noise. #268 put the explanations back.
  • Directory-index endpoints are named Subdirs and their helpers keep a Diridx suffix, because the scanner keys off that suffix. A rename for style would silently drop coverage.
  • Comma-joined fields use the CSV type, after []string fields that Proxmox returns as "a,b,c" broke the SDN round trip.
  • Every release with an apidiff incompatible change ships migration/vX.Y.Z.md (#335), with the exact apidiff commands and “themed sections with before/after code, not a flat dump”.

The pattern for all of them is the same: the first time I correct something it’s a review comment, the second time it’s a line in AGENTS.md.

The file rots like any other file

AGENTS.md is documentation that gets executed, and it goes stale. Right now its “Repo-specific gotchas” section warns about a replace directive in go.mod pointing at a local go-diskfs checkout. That replace only ever existed in my working copy, it has never been in a commit, and the file tells every agent to tiptoe around it anyway. It’s harmless, but it’s the same failure as a stale comment, with the difference that the reader takes it literally every single time.

Was it worth it

The numbers above happened, and 100% of the schema is wrapped with a mock and a unit test per endpoint, which I would never have typed by hand in six weeks of evenings. But the interesting work moved. I typed very little of the code and a lot of rules, did a lot of cherry-picking, and spent my review time on shape rather than syntax: is this the right type, the right receiver, the right place for this mock. Every change still went through a PR and CI. The agents are fast and literal, so the quality of what comes out is about the quality of what’s written down, and the cheapest time to write it down is the second time you see the mistake.
