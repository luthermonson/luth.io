Free Blog Hosting Using Hugo + Github Pages

Upgrade your Personal Blog Game with Apex Records for No Cost

January 27, 2022

4-Minute Read

Twitter

Facebook

Reddit

LinkedIn

Pinterest

Email

Since I just rode this merry-go-round here is a quick overview of how you can get a professional looking personal blog with custom DNS. It takes minimal effort, costs nothing and runs completely out of a single Github Repository.

Prerequisites

You’ll need to do your own homework on how to use Hugo. You should have a Github account and a decent understanding of using git and getting changes committed and pushed to a repo. You should also have a domain and know how to do some basic DNS changes. The only thing you likely can’t get for free is a domain name, since registrars charge registration costs. But you can get introductory $0.99USD domains for the first year if you shop around and don’t care what TLD you end up with. For reference, luth.io cost me $30/year to register with CloudFlare.

DNS

Do this part first… it can take a while to propagate depending on your provider. Getting it out of the way will just make your life easier. What you are trying to do is use Github Pages with an Apex record for your domain. This will let something like https://luth.io be the place where people find your blog. Apex record support for a hosting service will let you bypass using subdomains like https://blog.luth.io which are called CNAMEs in DNS terms. You’re looking for A, ALIAS or ANAME records. When pointed at the root of your domain they need to be an IP address.

This requires Github Pages to support Apex records and provide IP addresses to point your DNS to. This was easy to find since Github Pages has an entire write-up in its help documentation. Following the advice from the article you will need to configure 4 A records and 4 AAAA records. For validation with Github you should add a CNAME for www pointed to your Github Pages username DNS e.g. luthermonson.github.io.

# A Records
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153

# AAAA Records
2606:50c0:8000::153
2606:50c0:8001::153
2606:50c0:8002::153
2606:50c0:8003::153

# CNAME www
<githubusername>.github.io

Verifying your Domain with Github

You will need to add your domain to Github and add a DNS TXT record to be able to add it to a repository later. Go to your Github Pages settings for your account (not repository) and Click “Add a Domain”. Follow the instructions by typing your domain and clicking next. You’ll get the DNS TXT records to validate your Domain with Github Pages.

Grab the details from the Verification Step, add the TXT record to your DNS Provider and then click Verify.

Github Repository

You will need a Github Repository to house your Hugo blog and all the content. This will be where you serve your pages. Play with Hugo and create your blog, pick a theme and get used to the Hugo tool chain. Hugo will create a directory structure. By default when you run the hugo cli command it will generate your blog and place all contents in the ./public directory. Github Pages can NOT serve from anything other than the root ./ and the subdirectory ./docs. For our purposes to serve from one Github Repository we will use ./docs. To fix Hugo to publish to ./docs you can simply add a config line of publishDir = "docs" to the config.toml. When you now run hugo cli it will generate all files to the ./docs directory and prime your repository for serving via Github Pages.

Summary

Configure your DNS properly and use the free Github Pages service. Then you can easily host your personal blog at no cost on your own personal vanity domain name from a single Github Repository. Configure Hugo to use the ./docs directory to adhere to Pages standards and you’ll be able to effortlessly set up your Blog. Go henceforth and buy up some novelty domain names and get to blogging!
